# Данные из часов и весов

**Android + твои весы и часы — конкретные шаги: [`android.md`](android.md).**

Приложение не ходит в интернет и не хранит пароли — это его сильная и слабая сторона.
Поэтому данные попадают в него тремя способами, от простого к автоматическому.

## Уровень 0. Ручной импорт файла (работает всегда)

Дневник → «Импорт файла» → выбрать `.csv`, `.json` или `.txt`.

Понимает:

- CSV с `;`, `,` или табуляцией, с русскими и английскими заголовками;
- запятую как десятичный разделитель (`98,4`) и точку (`98.4`);
- даты `23.11.2026`, `2026-11-23`, `2026-11-23T19:00:00`, `11/23/2026`;
- сон в часах (`7.5`) и в минутах (`450`);
- воду в литрах (`2,8` → 11 стаканов) и в стаканах;
- названия колонок: `дата/date/time`, `вес/weight`, `шаги/steps`, `сон/sleep`, `ккал/kcal/calories`, `белок/protein`, `вода/water`, `пиво/beer`, `боль/pain`.

Уже проверенные источники: **openScale** (весы Mi Scale 2, с составом тела и без), **Zepp** (`Time,Steps,Sleep (h),Weight (kg)`), **Health Connect** (широкий `Date,Steps,...` и длинный `date,metric,value`), собственный CSV и JSON-бэкап.
Файл весов с колонками состава тела распознаётся особо: берётся только вес, а «water» (вода организма) и «calories» (базовый обмен) в дневник не пишутся.

Импорт не затирает старое: совпадающие даты обновляются только там, где пришли новые значения.
Повторный импорт того же файла ничего не ломает.

Шаблон (его же показывает приложение):

```
date;weight;steps;sleep;kcal;protein;water;beer;pain
2026-11-23;98,4;6200;7;1870;152;11;0;2
```

## Уровень 1. data.json + локальный сервер (полу-автомат)

Если приложение открыто по `http://` (не по `file://`), оно при каждом запуске
пытается забрать `data.json` из своей папки и тихо влить его в дневник.

1. Положить рядом с `index.html` файл `data.json` (образец — `sync/data.example.json`).
2. Запустить сервер: двойной клик по `Запустить.cmd` в корне папки
   (или `powershell -ExecutionPolicy Bypass -File sync\serve.ps1`).
3. Открыть `http://127.0.0.1:8766/`.

Форматы `data.json`:

```json
{ "records": [ { "date": "2026-11-23", "weight": 98.4, "steps": 6200, "sleep": 7 } ] }
```

```json
{ "days": { "2026-11-23": { "weight": 98.4, "steps": 6200 } } }
```

Второй формат — это обычный экспорт приложения (Дневник → Экспорт), так что
`data.json` можно просто заменять свежим бэкапом.

Дальше `data.json` может писать кто угодно: скрипт, планировщик задач Windows,
Tasker на Android, выгрузка из другого приложения. Приложение подхватит его
при следующем открытии.

## Уровень 2. Мосты из Amazfit / Xiaomi (нужна настройка один раз)

Точных «включил и поехал» путей два, оба требуют посредника — прямого API
у Zepp для сторонних приложений нет.

**a) Через экспорт Zepp / Zepp Life.** В приложении есть выгрузка данных аккаунта
(профиль → конфиденциальность → экспорт). Файл весит много и содержит всё подряд,
поэтому его удобнее один раз превратить в наш CSV скриптом — тогда дальше это
кнопка «Импорт файла» раз в месяц.

**b) Через Android + Health Connect.** Zepp выгружает шаги, сон и пульс в
Health Connect (Android 14+, в Zepp это «Настройки → Сторонние приложения»).
Дальше любой коннектор, который умеет отдавать CSV/JSON (например, Health Sync
или Health Auto Export — у второго есть готовый JSON), пишет файл, который
приложение импортирует. На iPhone путь другой: Health Auto Export → JSON → «Импорт файла».

**c) Весы Xiaomi Mi Smart Scale 2.** Они не умеют отправлять данные никуда, кроме
приложения-хозяина (Zepp Life / Mi Fit): протокол BLE, вес уходит по broadcast.
Варианты:

- взвешиваться и раз в неделю переписывать одно число в «Сегодня» — 15 секунд;
- либо отдельный слушатель BLE на компьютере/Android (например, Gadgetbridge
  на Android видит весы и умеет экспорт; на Windows — скрипт на Python с `bleak`),
  который пишет `data.json`. Это уже «сделай сам», и я могу собрать такой скрипт,
  если нужно.

**d) Часы Amazfit T-Rex 2.** Официально — только через Zepp. Прямая альтернатива —
Gadgetbridge: он поддерживает T-Rex 2, но требует один раз вытащить auth-key
из аккаунта Zepp, после чего часы работают без облака и умеют экспорт в файлы.
Это самый «чистый» путь по приватности, но настройка на вечер.

## Что писать в data.json, если делаешь свой скрипт

Только то, что реально есть: `date` обязательна, остальное — по наличию.
`pain` (0–10) и `beer` (л) из часов не придут никогда — их вносим руками.

## Проверено

- Импорт CSV/JSON: 27/27 автотестов (русские и английские заголовки, запятая,
  даты в четырёх форматах, сон в минутах, вода в литрах, повторный импорт без дублей,
  понятные ошибки на битый файл).
- Авто-подхват `data.json` по `http://127.0.0.1:8766/`: 8/8 — данные появились в
  дневнике сами, service worker активен, повторное открытие не дублирует записи.
